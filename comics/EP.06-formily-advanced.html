EP.06 自定义组件不是逃离 Schema 的后门 ​

对应章节：guide/06-formily-advanced

剧情回顾 ​

  1. 困境：标签君遇到 Schema 写不出的金额输入框，第一反应是整页改回 JSX；码叔拦住他，因为这一页改回去，后面所有页面都会跟着改回去。
  2. 揭秘：解决方案是注册表 + 字符串名：组件实现留在代码里，用 connect + mapProps 接入字段状态，Schema 里只写 MoneyInput。
  3. 实证：像素酱把布局与复用也写进配置：gridSpan 控制占列，对象展开复用公共字段片段。
  4. 结案：码叔用实时 JSON 编辑器划出底线：能序列化、能存库、能跨端的才叫配置；塞函数的 JSON 只是换了写法的代码。

知识点拆解 ​

第一格：什么时候真的需要自定义组件 ​

不是所有「Schema 写不出来」都需要自定义组件。先判断三件事：内置组件能不能通过 x-component-props 满足；能不能用 reactions 组合已有字段；只有确认需要新的交互或格式化逻辑时，才写组件。

金额输入框需要 ¥ 前缀、两位小数、null 转 0，这些用内置 NumberPicker 加 props 也能接近，但公司统一组件还包含格式化与业务校验。此时自定义组件是合理的；如果只是改个 placeholder，就不值得新增一个注册项。

第二格：connect 与 mapProps 的边界 ​

connect 把组件包成 observer，让字段变化时只重渲染这个组件。mapProps 声明哪些字段状态变成 props：

tsx
mapProps({ value: true, onChange: true, disabled: true });

只映射需要的状态，不把整个 field 透传给第三方组件。否则组件可能绕过模型直接改状态，联动、校验、提交都会失控。只读字段只映射 value，不需要 onChange，但它仍然是表单字段，仍然参与取值与提交。

第三格：布局与复用 ​

FormGrid 提供栅格上下文，FormItem 读取 x-decorator-props.gridSpan 决定占几列。把布局写进 Schema 后，同一份字段配置换个 maxColumns 就能重排，不需要改每个字段的样式。

Schema 复用用对象展开：把公共片段抽成对象，再展开进页面 Schema。它做的是浅合并，优点是零依赖、可读、可测试；边界是字段级覆盖之后会变成两份独立配置，后续仍可能漂移。需要参数化时抽函数，但要接受失去可序列化。

第四格：为什么实时编辑器只收纯 JSON ​

实时编辑器的流程只有三步：JSON.parse 文本、校验根节点是 type: "object"、交给同一个 SchemaField 渲染。它故意不接受函数，因为一旦 Schema 里有函数，文本就无法解析，配置无法存库，跨端也无法执行。

这条限制不是技术洁癖，而是产品边界：低代码平台的配置必须能被存储、传输、diff、回滚。需要函数的逻辑应该放在自定义组件、函数式 reactions 或后端规则引擎里，而不是塞进配置文本。

坑点清单 ​

  1. 只 connect 不 mapProps：组件拿不到 value/onChange，表现是「能看不能改」。
  2. 把整个 field 透传给第三方组件：组件可能绕过模型改状态，联动与校验失控。
  3. 把只读展示写成纯 UI：值不进模型，提交时还得再算一遍。
  4. gridSpan 写到 x-component-props：FormItem 读的是 x-decorator-props，写错不生效。
  5. 实时编辑器不捕获解析异常：一个坏字符就让页面白屏。
  6. Schema 里塞函数或正则字面量：无法序列化，存库与跨端都会失败。

自测 ​

1. 自定义字段为什么要在 Schema 里写字符串名，而不是组件对象？

因为 Schema 需要被序列化、存库、跨端传输和做版本 diff。组件对象包含函数与运行时依赖，无法被 JSON 表达。字符串名 + 注册表把配置与实现分离，组件升级不影响历史配置。

2. 只读展示字段为什么也要用 connect 接入模型？

因为它需要参与取值、校验、联动和提交。写成纯 UI 组件后，值只存在于视图层，提交时拿不到，只能在提交函数里重算，规则又散了一处。用 mapProps({ value: true }) 保留字段身份即可。

3. 实时编辑器为什么不允许在 JSON 里写校验函数？

因为函数无法被 JSON.parse，配置也就无法存库、跨端和 diff。需要函数的场景应放到代码里的自定义组件、函数式 reactions 或后端规则引擎，配置文本只保留可序列化的结构。
