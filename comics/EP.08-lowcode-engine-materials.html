EP.08 物料不是组件，是一份三方都能读的协议 ​

对应章节：guide/08-lowcode-engine-materials

剧情回顾 ​

  1. 困境：标签君写好了 OrderSummary 组件，本地 import 正常，拖进画布却报「这不是一个 React 组件」。
  2. 揭秘：码叔指出设计器、渲染器、出码器读的是同一份物料描述，缺了包名、导出名、是否解构，渲染器只能拿到整个模块对象。
  3. 实证：像素酱补上 npm.exportName 与 destructuring，再注册自定义 LabToneSetter，右栏出现「青 / 紫 / 琥珀」三个色调按钮。
  4. 结案：码叔总结物料三件套——组件实现、元数据、运行时资源；少一项，就会出现「能渲染、不能编辑」的半成品。

知识点拆解 ​

第一格：为什么 import 成功，画布却报错 ​

组件在业务代码里能 import，只说明模块系统能找到它。设计器走的是另一条路径：它先读 componentsMap，再按 package + version + exportName 去运行时资源里取组件。如果元数据只写了包名，没有写导出名，渲染器拿到的是整个模块对象；React 尝试把模块对象当组件渲染，就报 Card is not a react component。

这类错误最迷惑人的地方是「代码明明没错」。组件本身确实没错，错的是描述：物料协议没有把「这个模块里的哪个导出」说清楚。

对应正文：原理拆解。

第二格：packages 与 components 的分工 ​

  • assets.packages：运行时资源清单。回答「这个包从哪加载、全局变量叫什么、有哪些 CSS」。它只关心资源，不关心组件。
  • assets.components：组件元数据清单。回答「有哪些组件、标题是什么、怎么分组、有哪些属性、用什么 Setter」。

两者是并列关系，不是包含关系。把组件元数据塞进 packages[].components，引擎的 assetsTransform 读不到，典型报错是 Cannot read properties of undefined (reading 'components')。正确写法是顶层同时给 packages 和 components，让资源与描述各归各位。

第三格：Setter 的双向协议 ​

Setter 接收 value，通过 onChange 把新值写回节点。它是一个受控组件，但不是业务组件：它不负责渲染订单摘要，只负责编辑某个属性。

自定义 Setter 的注册入口是 ctx.setters.registerSetter({ LabToneSetter })，元数据里用 setter: { componentName: "LabToneSetter" } 引用。两条链路必须同时成立：注册表里有这个 Setter，元数据里引用了这个 Setter。缺前者，右栏空白；缺后者，Setter 永远不会被调用。

第四格：物料三件套 ​

  1. 组件实现：真实的 React 组件，决定运行时长什么样；
  2. 元数据：npm、props、setter、分组，决定设计器怎么展示与编辑；
  3. 运行时资源：library 与 urls，决定渲染器从哪里加载它。

三件套齐全，物料才是可分发资产：可以放进物料市场，可以被另一个项目引用，可以被出码器还原成 import 语句。只有组件实现，那只是一段业务代码，不是物料。

坑点清单 ​

  1. npm 只写 package 和 version：必须补 exportName 与 destructuring，否则渲染器取到模块对象。
  2. 把 components 写进 packages[]：引擎只读顶层 components，层级错一次，排查半天。
  3. Setter 只注册不引用：元数据里要写 setter.componentName，否则右栏不会出现。
  4. 自定义组件撑爆容器：Next Card 内容区高度有限，组件过高会出现「展开」，应先缩小尺寸再排查协议。
  5. 改完物料不刷新 iframe：模拟器缓存旧资源，改完 lab-materials.js 需要整页刷新。

自测 ​

1. `assets.packages` 与 `assets.components` 各自回答什么问题？

packages 回答「运行时资源从哪来」：包名、版本、全局变量名、资源 URL、CSS。components 回答「有哪些组件、怎么描述」：组件名、标题、分组、属性、Setter、npm 导出信息。两者并列，不能互相嵌套。

2. 为什么 `npm` 里必须写 `exportName` 和 `destructuring`？

渲染器需要知道从模块的哪个导出取组件，以及这个导出是否需要解构。只写包名时，渲染器拿到整个模块对象，React 会报「不是 React 组件」。exportName 指定导出名，destructuring: true 表示按解构方式取。

3. 自定义 Setter 要满足哪两个条件才会出现在右栏？

第一，通过 ctx.setters.registerSetter 注册到 Setter 注册表；第二，组件元数据的属性里用 setter: { componentName: "..." } 引用它。注册与引用缺一不可。
