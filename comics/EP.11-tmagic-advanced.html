EP.11 事件联动三种打法：comp / code / data-source ​

对应章节：guide/11-tmagic-advanced

剧情回顾 ​

  1. 困境：运营要求一个按钮"点了能弹窗、能让另一个组件翻面、能刷新数据源"，标签君试图在一个 Vue 组件里写三个 click listener。
  2. 揭秘：码叔把三种联动方式列在一张卡片上——CODE 执行 DSL 里预定义的 codeBlock，COMP 调目标组件的 instance method，DATA_SOURCE 调数据源的 setData / request。
  3. 实证：像素酱在画布上点了按钮，弹窗弹出来 → 动画卡翻了一面 → 柱状图刷新了数据。
  4. 结案：码叔收束到「EventHelper 统一 dispatch，三种 actionType 只是 switch 分支」——理解链路，比记住 API 更重要。

知识点拆解 ​

第一格：一个按钮三种联动 ​

按钮点一下想干三件事——串行 await 执行、flowState 可中断。EventHelper 在 dispatch 时按顺序遍历 actions 数组，每个 actionType 对应一个 switch 分支：

ts
async actionHandler(actionItem, fromCpt, args, flowState) {
  if (actionItem.actionType === ActionType.COMP) ...
  else if (actionItem.actionType === ActionType.CODE) ...
  else if (actionItem.actionType === ActionType.DATA_SOURCE) ...
}

所以三件事必须同属于一个 actions: [...] 数组，按顺序写在前一个之后。如果想条件跳过（比如 stock > 0 才弹窗），把条件写进 code block 里，或用 flowState.abort() 在 CODE 里中断后续 COMP 和 DATA_SOURCE。

对应正文：原理拆解 · 事件联动三种 Action。

第二格：组件四件套 ​

写一个业务组件不是"写一个 Vue 文件"那么简单——四件套决定了：

文件决定什么被谁用到
index.vue运行时渲染 + 事件 emitruntime 的 App 实例
formConfig编辑器右侧表单有哪些字段编辑器 propsConfigs[type]
initValue新组件拖入画布时的 DSL 值编辑器 propsValues[type]
event可触发的事件名 + 对外暴露的方法eventMethodList[type]

lab 里 AnimatedCard 在 onMounted 里把 flip 方法挂到 node.instance.flip = flip——这步是 COMP 联动能调通的关键。声明了 methods 数组但没实际挂方法，联动静默跳过，也不报错。

第三格：数据源四件套 ​

数据源比组件多一个 dataSource 类：它继承 @tmagic/data-source.DataSource（静态基类）或 HttpDataSource（HTTP 基类），重写 get type() 和 init()。DataSourceManager.register(type, cls) 在 runtime new TMagicApp 之前或组件 import 后立即调用即可。

组件里想引用数据源字段，formConfig 写 { type: "data-source-field-select" }，编辑器会弹出数据源选择器；运行时 core 的 compiledNode 会把 config.fields.xxx 自动替换成真实数据。

第四格：发布链路为什么走 CLI ​

tmagic 官方有 @tmagic/cli，命令是 tmagic entry——它扫 tmagic.config.ts 的 packages 列表，把每个组件的 formConfig / initValue / event 拼成一份 UMD（config-entry.js / value-entry.js / event-entry.js / ds-config-entry.js / ds-value-entry.js），编辑器通过 asyncLoadJs 异步加载这五份，自动回填 propsConfigs / propsValues / eventMethodList / datasourceConfigs / datasourceValues。

lab 跳过了这步，手动 import + 手动回填——因为体量小、手动更可控。但如果你要做真正的发布流水线（runtime 一个工程，编辑器一个工程），cli 是标准做法。

逐格解读 ​

第一格：一个按钮三种联动 ​

画面：画布上有一个"多功能按钮"组件，旁边飘着三个箭头：① 弹窗（alert 图标）；② 翻面（卡片图标）；③ 柱状图刷新（柱状图 + 刷新图标）。箭头根部连着 DSL 的 actions: [CODE, COMP, DATA_SOURCE] 数组。

台词：

像素酱：「按钮点一下能调三个东西？」 码叔：「对，串行跑；flowState.abort 能中途停。」

第二格：组件四件套 ​

画面：四个带编号的卡片：① index.vue（运行时本体）；② formConfig（右侧表单）；③ initValue（拖入默认 DSL）；④ event（事件 / 方法声明）。第四张卡片上有一条虚线指向 node.instance.flip = flip 的代码行。

台词：

码叔：「声明了 methods 不够，要真把方法挂 instance 上。不然联动调的是 undefined。」

第三格：数据源四件套 ​

画面：一个 HttpDataSource 类，旁边 formConfig 里有 { type: "data-source-field-select" } 字段；下面是 DataSourceManager.register("my-http", MyDataSource)；再下方是组件里价格字段自动变成真实数据的箭头。

台词：

像素酱：「哦原来 data-source-field-select 是 formConfig type，不是 DSL 里随便写的！」

第四格：发布链路 ​

画面：tmagic.config.ts → tmagic entry → 五份 .js（config / value / event / ds-config / ds-value）→ 编辑器 runtimeUrl + /entry/config.js 异步加载。旁边有一个"lab 简化版"的虚线框，指向手动 import + 手动回填。

台词：

码叔：「完整发布走 cli；lab 跳过，手动 import 更可控。」

坑点清单 ​

  1. COMP 联动调不动 flip，控制台不报错 — 声明 methods 数组只是让编辑器右侧面板能选到 flip 这个名字；真正要调通，必须在组件 onMounted 里 node.instance.flip = flip 显式挂方法。没挂的话 EventHelper 调时会静默跳过，也不报错。
  2. CODE action 执行静默跳过 — 在 code block 的 content 里抛 throw new Error("hello from code block") 看 console，就能知道有没有执行到；也可临时在 EventHelper.actionHandler 里打 log。静默跳过通常是 codeId 写错或前一个 action 用 flowState.abort 中断了。
  3. 数据源 register 了但编辑器找不到 — DataSourceManager.register(type, cls) 必须在 new TMagicApp({...}) 之前或组件 import 之后立即 调，不能等到 useDsl / useEditorDsl 初始化后。初始化后再注册，编辑器左侧数据源面板已经构建完列表，不会再刷新。
  4. formConfig type 收窄过严 TS 报错 — 把 propsConfigs 的类型声明改成 any[] 绕过。运行时 @tmagic/form 支持更多 type（color-picker、boolean、rate、slider、date-picker 等），但 TS 的 FormItemConfig 类型联合没完全覆盖。官方 playground 也是 as any。
  5. style 字段写了 left: 30 没单位 — 必须 left: "30px" 或 left: "30%"。数字在 CSS 里是非法单位值，画布的绝对定位布局会错乱。initValue 里直接写字符串即可，编辑器不会自动帮你补单位。
  6. 自定义 type 和 runtime register key 不一致 — componentGroupList / propsConfigs / propsValues / eventMethodList 里用的 type 和 app.registerComponent(type, Component) 的 key 必须严格一致。有一处错，画布就渲染不出来（resolveComponent 返回 undefined）。

自测 ​

1. 自定义组件四件套（index.vue / formConfig / initValue / event）分别决定什么？lab 为什么手动 import + 手动回填而不用 @tmagic/cli？

四件套分工：

  • index.vue：运行时渲染本体 + 组件内部逻辑 + event emit（magic:common:events:click 等）；
  • formConfig.ts：编辑器右侧属性面板有哪些字段（type/text/name 数组，支持 text / color-picker / data-source-input / data-source-field-select 等）；
  • initValue.ts：新组件拖入画布时的初始 DSL 值（节点的默认 title / style / barColor 等）；
  • event.ts：组件可触发的事件名（events 数组）和对外暴露的方法名（methods 数组）——编辑器右侧"事件联动"面板作为源 / 目标选项。

lab 跳过 cli 的原因：体量小、手动更可控。cli 的 tmagic entry 会把每个组件的四件套拼成五份 UMD（config / value / event / ds-config / ds-value），编辑器通过 asyncLoadJs(runtimeUrl + "/entry/config.js") 异步加载后自动回填 propsConfigs / propsValues / eventMethodList / datasourceConfigs / datasourceValues。但 lab 只有 5 个组件，手动 import + 手动回填两行代码就搞定，引入 cli 的工程开销（tmagic.config.ts、.tmagic/ 目录、build:page / build:libs / build:playground 三条命令）远大于收益。真正做发布流水线时再走 cli。

2. EventHelper 的三种 actionType（CODE / COMP / DATA_SOURCE）分别做什么？执行模型是怎样的？flowState 在中间扮演什么角色？

三种 actionType 共用同一个 DSL.events[].actions[] 数组，EventHelper.actionHandler 内部 switch 分支，串行 await 执行：

  • CODE：调 app.runCode(codeId, params)，找到 DSL 的 codeBlocks[codeId].content 函数，传入 { app, params, dataSource, eventParams, flowState } 执行。code block 里可以调 app 的任何方法，甚至直接改其他节点的 DSL。
  • COMP：调 app.getNode(to).instance[methodName](fromCpt, ...args)。to 是目标组件 id，methodName 是组件 methods 数组里声明的名字。核心前提是目标组件真的在 node.instance 上挂了这个方法。
  • DATA_SOURCE：先查 dataSource.methods 数组里有没有同名方法（code block 形式），有就执行；没有就 fallback 到 dataSource[methodName]({ params })（类方法形式，如 request / setData）。

flowState：所有 action 共享同一个 flowState 对象，三个方法——abort() 中断后续所有 action、reset() 在所有 action 跑完后自动调、get / set 可以在多个 action 间共享中间状态。用 abort() 就能实现"条件联动"——比如 stock <= 0 时第一个 CODE action 直接 abort，后面的 COMP 翻卡片、DATA_SOURCE 刷新都不执行。

3. tmagic 的数据源模型是什么？组件里想用数据源字段，formConfig 和 runtime 各要做什么？

数据源模型：@tmagic/data-source 提供基类 DataSource（静态数据源）和 HttpDataSource（继承它，加 url / method / headers / responseOptions / beforeRequest / afterResponse）。自定义数据源要：

  1. 继承其中一个基类；
  2. 重写 get type() 返回唯一字符串（不能用 static / http，tmagic 内置已占用）；
  3. 实现 init()（HttpDataSource.init() 内部自动调 request()）；
  4. 重写 formConfig / initValue / event 描述编辑器里能改什么。

formConfig 侧：组件的 formConfig 里写 { type: "data-source-input", name: "price" } 或 { type: "data-source-field-select", name: "priceField" }。data-source-input 让编辑器弹出"静态值 / 数据源模板"切换的输入框；data-source-field-select 直接从已注册数据源里选一个字段。

runtime 侧：DataSourceManager.register(type, MyDataSource) 必须在 new TMagicApp({...}) 之前调，否则编辑器数据源面板初始化时扫不到。组件 DSL 的 config.price 字段会被 core 的 compiledNode 自动编译——如果值是数据源模板字符串（如 &#123;&#123;ds_1.data.price&#125;&#125;），运行时 compiledNode 会把它替换成真实数据，组件渲染时直接拿到最终值，不用手动 watch。
