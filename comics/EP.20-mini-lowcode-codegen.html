EP.20 从 Schema 到可运行系统 ​

对应章节：guide/20-mini-lowcode-codegen

剧情回顾 ​

  1. 一份 Schema JSON：像素酱展示设计器产出的一份 Schema JSON，包含 page、text 等节点。
  2. 两个产物：Codegen 把 Schema 转换成两个产物——可运行的 .vue 文件（Vue 组件）和 .json 文件（Schema 原文）。
  3. 丢进去就能跑：标签君把产物丢到任意 Vue 项目里，不需要修改业务代码，直接 pnpm dev 就能跑起来。
  4. 进阶卷完成：码叔结案——进阶卷完成，你已理解低代码引擎全链路（Schema → Renderer → Designer → History → Plugin → Codegen），再用 amis / lowcode-engine 已看穿黑盒。

知识点拆解 ​

第一格：Schema 是中间产物 ​

Schema 是设计器的产出，但 Schema 本身不能直接在浏览器里跑。要变成可运行的系统，需要 Codegen（出码）把 Schema 转换成目标技术栈的代码。

Schema 的价值在于中间表示——它不绑定具体框架，同一份 Schema 可以出 Vue 代码、React 代码、甚至小程序代码。

第二格：两个产物 ​

mini-lowcode 的 Codegen 产出两个文件：

  1. .vue 文件：可运行的 Vue 单文件组件，template 部分由 Schema 转换而来。这个文件可以直接丢到任意 Vue 项目里运行。
  2. .json 文件：Schema 原文，供其他工具消费（如服务端渲染、二次编辑、跨端渲染）。

.vue 是面向「运行」的产物，.json 是面向「数据」的产物。两者配合，既保证可运行，又保留可编辑性。

第三格：为什么丢进去就能跑 ​

因为 Codegen 生成的 .vue 文件是标准 Vue 单文件组件，不依赖 mini-lowcode 的运行时。它只依赖 Vue 本身和基础组件库（如 text-comp、button-comp）。

这意味着：

  • 生成的代码没有黑盒运行时，可读、可调试、可二次修改；
  • 不需要在业务项目里引入 mini-lowcode 引擎；
  • 生成的代码性能和手写 Vue 一致。

对比「运行时渲染」方案（如 lowcode-engine 的出码），Codegen 生成的是静态代码，没有运行时开销。

第四格：全链路打通 ​

进阶卷六章（EP.15 是过渡，EP.16-20 是核心）从零搭建了完整的低代码引擎：

Schema（数据）→ Renderer（渲染）→ Designer（拖拽）→ History（撤销）→ Plugin（扩展）→ Codegen（出码）

每一层都亲手实现过，理解了每一层解决什么问题、有什么坑。再回头用 amis / Formily / lowcode-engine，就能看穿黑盒——知道它内部大概是怎么实现的，遇到问题能精准定位。

坑点清单 ​

  1. 出码产物依赖运行时：如果生成的代码依赖 mini-lowcode 的运行时组件，业务项目就要引入引擎，失去出码的意义。出码产物应该只依赖标准框架。
  2. 表达式出码要转译：Schema 里的 $&#123;&#123; name &#125;&#125; 表达式在出码时要转译成 Vue 的 &#123;&#123; name &#125;&#125; 模板语法，不能原样输出。
  3. 事件出码要生成 handler：Schema 里的 onClick 事件在出码时要生成对应的方法，不能直接输出字符串。
  4. 样式出码要处理：Schema 里的 style 要转成 Vue 的 :style 绑定，class 要转成 :class。
  5. 出码产物要可读：生成的代码要格式化、有缩进、有注释，否则用户拿到手不敢改。
  6. 不要在出码阶段做太多转换：出码是 Schema → 代码的直译，不要在出码阶段做复杂的逻辑转换，复杂逻辑应该在 Schema 设计阶段就定好。

自测 ​

1. Codegen 为什么要产出 .vue 和 .json 两个文件，而不是只产出一个？

两个文件面向不同用途：

  1. .vue 文件：面向「运行」。是标准 Vue 单文件组件，可以直接丢到任意 Vue 项目里运行，不依赖 mini-lowcode 引擎。
  2. .json 文件：面向「数据」。是 Schema 原文，供其他工具消费——比如服务端渲染、二次编辑、跨端渲染（同一份 Schema 出 React 或小程序代码）。

只产出 .vue 会丢失可编辑性（用户改了 .vue 就无法反向同步回 Schema）；只产出 .json 则无法直接运行。两个文件配合，既保证可运行，又保留可编辑性。

2. 为什么出码产物不依赖 mini-lowcode 的运行时？

因为出码的目的是让业务项目能独立运行。如果生成的代码依赖 mini-lowcode 的运行时组件（如 Renderer、表达式求值器），业务项目就要引入整个 mini-lowcode 引擎，这违背了出码的初衷——出码就是为了摆脱引擎依赖。

出码产物应该只依赖：

  • 标准框架（Vue / React）；
  • 基础组件库（text-comp、button-comp 等简单组件）。

这样生成的代码可读、可调试、可二次修改，性能和手写代码一致。用户拿到产物后，mini-lowcode 引擎就可以「功成身退」了。

3. 进阶卷全链路指的是什么？走完一遍有什么价值？

全链路指的是低代码引擎的六大模块：

Schema（数据定义）→ Renderer（递归渲染）→ Designer（拖拽编辑）→ History（撤销重做）→ Plugin（扩展）→ Codegen（出码）

走完一遍的价值：

  1. 看穿黑盒：再用 amis / lowcode-engine 时，知道每个功能背后的实现原理，遇到问题能精准定位是哪一层的问题；
  2. 精准选型：理解每个模块的职责和边界，能根据需求判断该用哪个产品、该怎么组合；
  3. 二次开发：需要扩展现成框架时，知道从哪里切入、怎么写插件。

核心不是造轮子，而是理解轮子——理解了原理，工具才是工具，而不是黑盒魔法。
