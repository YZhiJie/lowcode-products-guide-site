第 08 章 · 物料协议：让设计器认识你的组件 ​

前置章节：第 07 章 · lowcode-engine 架构
所需环境：Node 22 LTS、pnpm 9.15.4；本章 lab 使用 React 16.14.0 + Fusion Next 1.24.18 + @alilc/lowcode-engine 1.3.4。
难度：★★★
本章交付物：一个自定义订单摘要物料 + 一个自定义色调 Setter；选中画布节点后，右侧能改属性，画布实时刷新。

第 07 章启动了一个设计器，但画布上的组件全是 Fusion Next 自带的。真实平台不可能只靠一套通用组件：订单摘要、审批流、指标卡、地图选点，这些业务组件才是平台的价值。问题在于，设计器并不认识你写的 React 组件；它只认识一份物料协议。协议写对了，组件就能被设计器展示、被模拟器渲染、被设置器编辑；协议写错了，组件存在也等于不存在。

本章要把「物料」从抽象概念变成可检查的字段。你会看到三个层次：组件实现（React 代码）、组件元数据（JSON 协议）、运行时资产（脚本与样式）。三者分别解决「怎么画」「怎么配置」「从哪里加载」。把这三层混在一起，是低代码平台最常见的返工来源。

本章你将获得 ​

读完本章，你应该能完成四件事：

  1. 说清物料协议里 package、library、componentName、npm、props 各自的含义；
  2. 写一个自定义业务组件，并把它接进设计器画布；
  3. 注册一个自定义 Setter，让业务属性出现在右侧设置面板；
  4. 判断一份物料该拆包还是合并，以及什么时候需要独立资产包。

本章 lab 在第 07 章工程上增加一个章节目录 08-lowcode-engine-materials。它不会重写启动逻辑，只增加一份资产、一个物料实现、一个 Setter 插件。这样你能清楚看到「物料扩展」与「引擎启动」是两个独立的关注点。

先看漫画 ​

这一话的冲突很典型：平台团队把业务组件写好了，React 里能正常渲染，但接进设计器后组件面板不显示，或者显示了却拖不进画布；好不容易拖进去，右侧属性面板只有一堆看不懂的英文键。排查半天发现，组件代码没问题，问题出在元数据：exportName 没写、destructuring 没开、属性 Setter 没注册。

码叔的判断是：物料不是「组件 + 文档」，而是「组件实现 + 元数据 + 运行资产」三件套。设计器读元数据，模拟器读运行资产，用户看到的是组件实现。三者缺一，链路就断。

如果你只记住一句话：组件能不能用，取决于协议是否完整，而不是代码是否漂亮。 逐格讲解、坑点清单和三道自测题在 EP.08 漫画讲解。

从一个真实问题说起 ​

运营希望页面上出现一个「订单摘要」卡片：标题可改、金额可改、色调可在青/紫/琥珀之间切换。前端很快写好了 React 组件：

tsx
function OrderSummary(props) {
  return (
    <div className={`summary summary--${props.tone}`}>
      <div>{props.title}</div>
      <strong>¥ {props.amount.toFixed(2)}</strong>
    </div>
  );
}

问题从「接进设计器」开始：

  • 设计器的组件面板里没有它，因为设计器不知道它存在；
  • 就算手动写进 Schema，画布也报「不是 React 组件」，因为运行期取组件的路径不对；
  • 选中后右侧只有空白，因为没有声明它有哪些属性；
  • 声明了属性，但「色调」只能填字符串，运营不知道该填什么。

这四件事对应四份配置：资产包登记、componentsMap 映射、组件元数据、Setter 注册。少任何一份，体验都会断在某个环节。本章的 lab 就是把这条链路完整跑一遍：OrderSummary 渲染在画布上，右侧出现「标题 / 金额 / 色调」，点色块能实时改颜色。

原理拆解 ​

物料协议的四个层次 ​

一份可用的物料，至少包含四层信息：

  1. 组件实现：真正的 React 组件，决定像素与交互；
  2. 组件元数据：componentName、title、props、configure，决定设计器怎么展示、怎么配置；
  3. npm 来源：package、version、exportName、destructuring，决定运行期怎么取组件；
  4. 运行资产：urls、library，决定模拟器 iframe 从哪里加载脚本与样式。

很多人把第 2 层和第 3 层混在一起写，结果元数据能显示、运行期却取不到组件。正确做法是让它们各司其职：元数据里的 npm 字段专门描述来源，props 专门描述属性。

packages 与 components 的分工 ​

引擎的 assets 对象有两个顶层字段，职责完全不同：

  • packages：运行时资源清单。每一项包含 package、version、library、urls。它回答「这个包在浏览器里叫什么、要加载哪些文件」。
  • components：组件元数据清单。每一项包含 componentName、title、props、npm。它回答「有哪些组件、每个组件怎么配置」。

第 07 章已经踩过一次：把组件元数据塞进 packages[].components，setAssets 会报 Cannot read properties of undefined (reading 'components')。原因是引擎的 assetsTransform 只读顶层 components，不会去包里找。这个错误信息看起来像「assets 没传」，实际是「层级放错」。

自定义物料也一样：labMaterialsPackage 只写运行时信息，orderSummaryMeta 放顶层 components。两者通过 npm.package 关联。

运行期取组件：exportName 与 destructuring ​

模拟器拿到 componentsMap 后，会按下面的逻辑取组件：

  1. 根据 npm.package 找到 libraryMap 里的全局变量名；
  2. 读取 window[library]；
  3. 如果 destructuring 为真，按 exportName 取属性；否则取默认导出；
  4. 如果 subName 存在，再取一层子组件。

所以元数据必须写：

ts
npm: {
  package: "lab-materials",
  version: "1.0.0",
  exportName: "OrderSummary",
  destructuring: true,
  subName: "",
}

exportName 决定取 LabMaterials.OrderSummary；destructuring 决定是「解构取属性」还是「取 default」。少了这两个字段，渲染器会拿到整个模块对象，然后报 OrderSummary is not a react component。这个报错不会告诉你缺字段，只会把模块对象打印出来，所以排查时要先看 componentsMap，再看组件代码。

Setter：把业务属性翻译成人能懂的控件 ​

Setter 是设计器右侧的属性编辑器。它接收固定 props：

  • value：当前节点的属性值；
  • onChange：改值回调，调用后引擎更新 Schema 并通知画布；
  • field：节点模型，需要读取上下文时使用。

内置 Setter 覆盖字符串、数字、布尔、下拉、样式、事件等常见类型。业务属性往往需要更直观的控件，例如「色调」用三个色块比下拉框更清楚。这时注册一个自定义 Setter：

ts
export function LabToneSetterPlugin(ctx: any) {
  return {
    init() {
      ctx.setters.registerSetter({ LabToneSetter });
    },
  };
}
LabToneSetterPlugin.pluginName = "LabToneSetterPlugin";

注册名必须与元数据里的 setter.componentName 完全一致。名字对不上，右侧会显示「未找到 Setter」，而不是报错。这也是一个典型的「静默失败」：协议不报错，但体验缺失。

iframe 里为什么还要再加载一次脚本 ​

设计器画布是 iframe，不是父页面的一个 div。父页面加载了 Fusion Next，不代表 iframe 里也有；iframe 的 window 是独立的。引擎的启动脚本只会从父页面复制 React、ReactDOM、PropTypes 等少数全局变量，物料库需要自己通过 packages[].urls 再加载。

所以自定义物料的资产包要写：

ts
const labMaterialsPackage = {
  package: "lab-materials",
  version: "1.0.0",
  library: "LabMaterials",
  urls: ["/lab-materials.js"],
};

public/lab-materials.js 是一个 UMD 风格脚本，内部直接读 window.React，把 OrderSummary 挂到 window.LabMaterials。父页面也加载同一份文件，供第 09 章的轻量预览复用。这里不要假设「只有一份 React」：父页面与 iframe 各有一份全局变量，组件必须能在两个窗口里都拿到 React。

产品对照 ​

物料体系不是 lowcode-engine 独有的，但各家的协议开放程度差别很大：

维度lowcode-engineamisFormilytmagic-editor
物料单位组件 + 元数据 + 资产包渲染器类型字段组件组件 + 配置
元数据位置assets JSON内置/自定义渲染器组件注册表编辑器配置
自定义属性Setter 插件配置项x-component-props属性面板配置
运行期加载包 + URL随主包随主包随编辑器
适合场景平台型搭建中后台页面复杂表单活动页

amis 的「物料」更像「渲染器类型」，扩展方式是注册一个新 type；Formily 的物料是字段组件，扩展方式是注册 x-component；lowcode-engine 的物料是一份完整协议，扩展成本最高，但能支撑组件市场、按需加载、独立发版。选型时要看你的组件会不会持续增加，而不是看第一版能不能跑。

如果一个平台只有二十个固定组件，且一年不变，用 lowcode-engine 的物料体系是过度设计；如果组件会按业务域增长到上百个，且需要独立版本与按需加载，这份协议就是必要投资。

动手实现 ​

第一步：写组件实现 ​

自定义组件放在 public/lab-materials.js，用 window.React.createElement 而不是 JSX，原因是它要被 iframe 直接加载，不经过打包。核心渲染逻辑很短：

js
function OrderSummary(props) {
  var tone = props.tone || "cyan";
  var palette = { cyan: {...}, violet: {...}, amber: {...} };
  return React.createElement("div", { style: {...} },
    React.createElement("div", null, props.title || "订单摘要"),
    React.createElement("div", null, "¥ " + Number(props.amount || 0).toFixed(2)),
  );
}

这里刻意不做数据请求、不做权限判断。物料实现只负责「给定属性怎么画」，业务逻辑属于页面运行环境，不属于物料。

第二步：写元数据 ​

元数据决定设计器认识哪些属性：

ts
const orderSummaryMeta = {
  componentName: "OrderSummary",
  title: "订单摘要",
  devMode: "proCode",
  npm: {
    package: "lab-materials",
    version: "1.0.0",
    exportName: "OrderSummary",
    destructuring: true,
    subName: "",
  },
  props: [
    { name: "title", title: "标题", setter: "StringSetter" },
    { name: "amount", title: "金额", setter: "NumberSetter" },
    { name: "tone", title: "色调", setter: { componentName: "LabToneSetter", props: {} } },
  ],
};

devMode: "proCode" 表示这是源码组件，不是低代码组件。props 里的 setter 可以是字符串（内置 Setter 名），也可以是对象（自定义 Setter + 配置）。tone 用对象形式，是因为它要指向我们自己的 Setter。

第三步：注册 Setter ​

Setter 本质是一个普通 React 组件。它不需要知道节点树，只需要读 value、调 onChange：

ts
function LabToneSetter(props: any) {
  const current = props.value ?? "cyan";
  return React.createElement(
    "div",
    null,
    TONES.map((tone) =>
      React.createElement("button", {
        key: tone.value,
        title: tone.label,
        onClick: () => props.onChange?.(tone.value),
        style: {
          background: tone.color,
          border: current === tone.value ? "2px solid #1f2329" : "2px solid transparent",
        },
      }),
    ),
  );
}

三个色块都设置了 title，一是无障碍提示，二是烟测可以稳定定位。点击后 onChange 触发，引擎更新节点属性，模拟器重渲染，画布上的 tone: amber 文案随之变化。

第四步：把资产接进章节 ​

第 08 章的资产包在第 07 章基础上追加两项：

ts
export const materialChapterAssets = {
  packages: [nextPackage, labMaterialsPackage, ...runtimePackages],
  components: [...nextComponents, orderSummaryMeta],
  sort: { groupList: ["精选组件"], categoryList: ["基础元素", "容器", "业务组件"] },
};

页面 Schema 里直接使用 OrderSummary，并在 componentsMap 里登记它。启动时 setAssets 先解析元数据，importSchema 再创建节点；模拟器加载 /lab-materials.js，按 npm 字段取到 LabMaterials.OrderSummary 并渲染。

第五步：验证链路 ​

跑 pnpm dev，打开 #/08，按顺序检查：

  1. 画布上出现「本周成交额」与金额；
  2. 点击该节点，右侧出现「标题 / 金额 / 色调」；
  3. 点「琥珀」，画布背景与文字颜色变化，tone: amber 出现；
  4. 打开控制台，没有 is not a react component 或 Setter 未找到。

pnpm smoke 会把这三步自动化，并截图到 screenshots/08-materials.png。烟测用「点击节点 → 断言右栏字段 → 点击色块 → 断言画布文案」作为完成信号，而不是只看组件是否出现，因为「出现」可能只是静态 Schema 渲染，没证明设置器与数据回写通了。

跑不起来？ ​

  1. 画布显示「未注册组件」：先看 componentsMap 是否登记了 OrderSummary，再看 npm.exportName 与 destructuring。
  2. 右侧没有「色调」：检查元数据里的 setter.componentName 是否等于注册名 LabToneSetter，以及插件是否在 extraPlugins 里。
  3. 点色块没反应：检查 Setter 是否调用了 props.onChange，以及值是否写回节点 props；可以在 onChange 里打日志确认。
  4. iframe 里报 LabMaterials is not defined：packages[].urls 是否包含 /lab-materials.js，以及该文件是否在 public 下可访问。
  5. 组件渲染成错误块：通常是取到了模块对象而不是组件，回到 npm 字段检查 exportName 与 destructuring。
  6. 改了元数据但画布没变：刷新页面；物料元数据在 setAssets 时建立索引，热更新不一定能重建索引。

避坑清单 ​

  1. 组件实现、元数据、运行资产三层要同时改。只改一层，链路一定断在别处。
  2. package 与 library 不是一回事。前者是 npm 包名，后者是浏览器全局变量名；@alifd/next 对应 Next。
  3. Setter 名字必须与元数据一致。不一致时设计器不报错，只是不显示控件。
  4. iframe 不会继承父页面的物料全局变量。所有运行资产都要通过 urls 再加载。
  5. 不要把业务请求写进物料。物料只负责渲染，数据由页面运行环境注入。
  6. 按业务域拆资产包。一个巨大资产包会让首屏加载与版本管理都失控。

小结与自测 ​

物料不是组件，而是一份三方协议：设计器读元数据，模拟器读运行资产，用户看组件实现。packages 管运行时资源，components 管组件元数据；npm.exportName 与 destructuring 决定运行期怎么取组件；Setter 决定属性怎么被编辑。四者齐全，自定义组件才真正「可用」。

1. 为什么组件能渲染，但设计器右侧没有属性？

因为渲染只依赖 componentsMap 与运行资产，属性面板依赖组件元数据里的 props。元数据缺失或 setAssets 没执行，画布仍可能渲染，但设计器不知道这个组件有哪些可配置项。

2. `npm.exportName` 与 `componentName` 有什么区别？

componentName 是 Schema 与组件面板里的逻辑名，exportName 是 npm 包实际导出的变量名。两者可以不同，例如 componentName: "OrderSummary" 对应 exportName: "OrderSummary"，也可以把多个逻辑组件映射到同一个导出。

3. 自定义 Setter 注册后不显示，先查什么？

先查名字：元数据 setter.componentName 必须等于 ctx.setters.registerSetter({ ... }) 里的键。再查插件是否注册、init 是否执行。名字不一致时引擎不会抛错，只会静默跳过。

下一步 ​

物料解决了「组件怎么被设计器认识」，但平台还缺「保存、预览、发布、出码」这些业务动作。第 09 章会写一个完整插件：通过 skeleton 扩展点往工具条加按钮，导出 Schema、写入 localStorage、做轻量预览、生成 React 代码。到那时你会看到，插件不是「外挂功能」，而是引擎留给平台的正式扩展面。
