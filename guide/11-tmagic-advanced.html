第 11 章 · 组件、数据、动画，一个都不能少 ​

前置章节：第 10 章 · tmagic-editor 基础
所需环境：Node 22 LTS、pnpm 9.15.4；本章 lab 仍使用 Vue 3.5.44 + element-plus 2.14.7 + @tmagic/editor 1.8.3。
难度：★★★
本章交付物：自定义柱状图 + 横幅 + 动画卡三个组件；按钮点击触发 code 弹窗；动画卡暴露 flip 方法可被 COMP 联动调用。

第 10 章我们把 lab 跑起来了，DSL 能推到画布、text / button / container 三个官方组件能渲染、保存 / 预览闭环通了。但这时你还是会觉得"好像离业务组件还有点远"——我写一个真正带业务逻辑的组件、让它能接接口、能被其他组件调用方法、能响应数据源变化，这些能力在哪？

tmagic-editor 对这几件事给了一套统一的扩展协议。自定义组件遵循四件套（index.vue / formConfig / initValue / event），数据源遵循四件套（dataSource / formConfig / initValue / event），事件联动统一走 ActionType 三种动作（COMP / CODE / DATA_SOURCE），页面发布走 @tmagic/cli 的 tmagic entry 生成五份 UMD 资源。

本章聚焦三件事：写一个真正的业务组件（柱状图）、接一条数据源、绑一个事件联动。lab 里同时给出 HeroBanner（横幅 + 点击 code action）和 AnimatedCard（动画卡 + flip method 被 COMP 联动），两个都是官方"四件套"的业务变体，你可以直接抄模板。

本章你将获得 ​

读完本章，你应该能完成四件事：

  1. 独立写一个带 formConfig / initValue / event 的自定义组件，在右侧面板出现属性表单、拖入画布有默认值；
  2. 看懂 EventActionItem 的三种 actionType，在 lab 里配好一个 code action 和一个 comp action；
  3. 接一条 HttpDataSource 或 StaticDataSource，在组件里通过 data-source-input / data-source-field-select formConfig 引用它；
  4. 理解"发布链路"——@tmagic/cli 生成的 config / value / event / ds-config / ds-value 五份 UMD 是给编辑器异步加载用的，runtime 侧直接手动 import 即可（lab 跳过了 cli）。

先看漫画 ​

这一话讲"一个按钮想干三件事"：① 点了弹窗（code action，执行 DSL 里 pre-写好的代码块）；② 点了让另一张卡片翻面（comp action，调目标组件的 method）；③ 点了刷新数据源列表（data-source action，调数据源的 setData / request）。三种 action 共用一个联动配置结构，区别只在 actionType 和附带字段：COMP 要 to + method，CODE 要 codeId + params，DATA_SOURCE 要 dataSourceMethod + params。

如果你只记住一句话：事件联动是 EventHelper 统一 dispatch 的，三种 actionType 只是 switch 分支。逐格讲解、坑点清单和三道自测题在 EP.11 漫画讲解。

从一个真实问题说起 ​

运营同学想在画布上拖一个柱状图组件，改改标题和颜色就能上线。你在技术评审里拍板"这还不简单"，然后第二天面对一堆问题：

  • 柱状图的表单字段怎么定义？categories 和 values 要能从 CSV 输入切到数据源字段选择
  • 组件里的 config.values 如果指向数据源字段，怎么自动响应刷新
  • 点击柱子要触发别的组件的方法，怎么让动画卡翻面

tmagic 给了一套标准化协议让这些问题可解：formConfig 负责"右侧能改什么"、initValue 负责"新组件的默认 DSL"、event 负责"组件能触发哪些事件 / 暴露哪些方法"。数据源同理，再多一个 dataSource 类负责 fetch / setData / request 方法。

原理拆解 ​

组件四件套 ​

官方 Vue 组件包（@tmagic/vue-button 等）的每个组件都有四个文件：

bar-chart/
├─ index.vue        # 组件本体
├─ formConfig.ts    # 编辑器右侧表单配置数组
├─ initValue.ts     # 新拖入画布时的初始 DSL
└─ event.ts         # 组件可触发的事件名 + 对外暴露的方法名

src/runtime/main.ts 里手动 import + registerComponent 就能让组件在画布渲染。formConfig / initValue / event 不会被自动注入编辑器——需要在 src/configs/props.ts 里手动 propsConfigs["bar-chart"] = barChartFormConfig。这是因为 lab 跳过了 @tmagic/cli 的 tmagic entry 生成步骤（cli 会自动扫 componentsPath 生成五份入口）。

formConfig 的每个字段是 { type, text, name }：

  • type: "text" → 普通文本输入
  • type: "color-picker" → 颜色选择器
  • type: "boolean" → 开关
  • type: "input" → 输入框（和 text 差别是多行）
  • type: "data-source-input" → 可切换"静态值 / 数据源模板"
  • type: "data-source-field-select" → 从已注册数据源里选一个字段

initValue 是拖入时塞进 DSL 的初始节点：{ type: "bar-chart", title: "...", barColor: "...", style: { width, height } }。

event 数组声明组件能触发的事件名（供编辑器右侧"事件联动"面板作为源选项），methods 数组声明组件对外暴露的方法名（作为联动目标）。

事件联动三种 Action ​

DSL 里每个组件都可以声明 events：

ts
{
  events: [
    {
      name: "magic:common:events:click",   // 事件名，COMMON_EVENT_PREFIX 前缀
      actions: [
        { actionType: "code", codeId: "code_5336", params: { age: 12 } },
        { actionType: "comp", to: "animated-card_1", method: "flip" },
        { actionType: "data-source", dataSourceMethod: ["ds_1", "request"], params: {} },
      ],
    },
  ],
}

三种 actionType 在 EventHelper.actionHandler 里按顺序 switch：

  1. ActionType.CODE：调 app.runCode(codeId, params)，DSL 的 codeBlocks[codeId].content({ app, params, dataSource, eventParams, flowState }) 会被执行。flowState.abort() 可以中断后续 action（实现"条件联动"）。
  2. ActionType.COMP：调 app.getNode(to).instance[methodName](fromCpt, ...args)。所以 AnimatedCard 必须在 node.instance 上挂 flip 方法——lab 里在 onMounted(() => { node.instance.flip = flip })。
  3. ActionType.DATA_SOURCE：调 app.runDataSourceMethod(dsId, methodName, params)，先查 dataSource.methods 数组里有没有同名方法（code block 形式），有就执行；没有就 fallback 到 dataSource[methodName]({ params })（类方法形式）。

执行是串行 await 的——前一个没结束（或没 abort），后一个不会开始。flowState.reset() 在所有 action 跑完后自动。

数据源四件套 ​

@tmagic/data-source 提供两个内置数据源：DataSource（静态基类）和 HttpDataSource（继承它、加 url / method / headers / responseOptions / beforeRequest / afterResponse）。自定义数据源需要：

  1. 写一个类 extends DataSource（或 HttpDataSource）
  2. 重写 get type() 返回唯一字符串（在 datasourceConfigs 里用这个 type）
  3. 实现 init() —— 做初始化；HttpDataSource.init() 内部会调 request()
  4. 重写 formConfig / initValue / event 描述编辑器里能改什么

注册：DataSourceManager.register("my-ds", MyDataSource)。lab 里没写自定义数据源（聚焦组件），但 data-source-input / data-source-field-select 已经在 formConfig 类型里了，后续接只需按四件套补一份。

发布链路（@tmagic/cli 视角） ​

官方 playground 走的是"编辑器 + runtime + cli 三件套"：

  1. runtime/vue/tmagic.config.ts 声明 packages（组件 npm 包路径）
  2. npm run tmagic（即 tmagic entry）扫描 packages，生成 .tmagic/async-comp-entry.ts 等 5 份入口（comp-entry / config-entry / value-entry / event-entry / datasource-entry）
  3. runtime 通过这些入口 import 组件、formConfig、initValue、event；build 产出 page / playground / entry/ 三份产物
  4. 编辑器通过 runtimeUrl + '/entry/config.js' 异步加载五份 UMD，自动回填 propsConfigs / propsValues / eventMethodList / datasourceConfigs / datasourceValues

lab 跳过了 cli，手动 import + 手动回填，因为体量小。如果你要做完整发布，可以把 labs/tmagic-editor/runtime/ 拆成独立 npm 包，走这条链路。

额外补充：为什么手动 import 而不是 @tmagic/cli ​

你可能会问：tmagic 官方有 @tmagic/cli，命令是 tmagic entry，它能自动扫 packages 目录、生成五份入口文件、编辑器侧 asyncLoadJs 自动回填 propsConfigs —— 为什么 lab 不这么做？

答案是工程权衡。让我们把两种方案拆开对比：

CLI 方案的完整链路长这样：

  1. runtime 工程里建 tmagic.config.ts，声明 packages 数组——每个元素是 { name: "bar-chart", path: "./components/bar-chart" } 或 npm 包名；
  2. @tmagic/cli scan 扫 packagesPath 下的目录结构，对每个组件的四件套做静态分析（读取 formConfig / initValue / event），生成一份 metadata.json；
  3. tmagic entry 根据 metadata.json 生成 .tmagic/comp-entry.ts（runtime 用）、.tmagic/config-entry.ts（编辑器 propsConfigs）、.tmagic/value-entry.ts（propsValues）、.tmagic/event-entry.ts（eventMethodList）、.tmagic/ds-config-entry.ts（datasourceConfigs）、.tmagic/ds-value-entry.ts（datasourceValues）；
  4. runtime 的 Vite build 配置里 rollupOptions.output.manualChunks 会把这五份入口单独打成独立 chunk（entry/config.js 等）；
  5. 编辑器启动时 runtimeUrl + "/entry/config.js" 通过 script 标签或 import() 异步加载，加载后自动 merge 到 propsConfigs 全局对象里——新组件出现在左侧面板、右侧面板出现表单字段，编辑器不需要任何硬编码。

这条链路的优势是：组件完全由 runtime 侧定义，编辑器不感知。新增组件只要在 runtime 里写四件套、跑一次 tmagic entry、重新 build，编辑器自动拿到新组件。但劣势也很明显：

  • 需要维护两份工程（runtime / editor），或至少 runtime 要有独立的 build:page / build:libs / build:playground 三条命令；
  • tmagic.config.ts 的 packages 路径声明容易写错（本地相对路径 vs npm 包路径），错了 scan 阶段就扫不到；
  • .tmagic/ 目录是 cli 自动生成的，不建议手动改，意味着调试时看不到中间产物；
  • asyncLoadJs 的加载失败没有好的 error handling——网络抖动或 build 路径改了，编辑器只是拿不到组件，不会报错。

手动 import 方案（lab 用的）只有三步：

  1. runtime/main.ts 里 app.registerComponent("bar-chart", BarChart)；
  2. 编辑器 App.vue 里 <script setup> 顶部 import 四个 meta 文件：import { barChartFormConfig } from "../components/BarChart.meta"；
  3. configs/props.ts 里 propsConfigs["bar-chart"] = barChartFormConfig、propsValues["bar-chart"] = barChartInitValue、eventMethodList["bar-chart"] = barChartEvent。

手动方案的优势：全部在同一个工程里，IDE 跳转能到源码，TypeScript 检查能到类型，改组件名同时能收到编译错误。劣势是新增组件要改三处——但 lab 里只有 5 个组件，三处修改比维护 cli 工程成本低。

真正的分界线是"组件数量"：当 runtime 有 20+ 组件、多个开发同事并行开发、或者需要跨工程复用组件库时，cli 的"自动扫描 + 异步加载"就能体现出工程化优势——新增组件零改动编辑器、组件库可以独立发布 npm 包。但教学级 lab 只有 5 个组件、一个人开发、一个工程搞定，手动 import 更清晰。

如果你想在 lab 基础上迁移到 cli 方案，步骤很清晰：把 labs/tmagic-editor 拆成两个目录（editor / runtime）、runtime 加 tmagic.config.ts 声明 packages、加 build:page / build:libs / build:playground 脚本、editor 侧把 propsConfigs / propsValues / eventMethodList 清空改成 asyncLoadJs。迁移完成后新增组件就不需要动 editor 了——但你会失去"在 IDE 里跳转组件 meta 文件"的便利。

动手实现 ​

1. 启动第 11 章 ​

bash
cd labs/tmagic-editor
pnpm dev
# URL hash 切换：#11 解锁自定义组件分组
# 或直接访问 http://localhost:5177/#11

左侧面板应该多一个"自定义组件"分组，里面有柱状图 / 横幅 / 动画卡三项。

2. 柱状图：从 formConfig 到运行时渲染 ​

src/components/BarChart.meta.ts 是四件套之一：

ts
export const barChartFormConfig: any[] = [
  { type: "text", text: "标题", name: "title" },
  { type: "input", text: "分类（英文逗号分隔）", name: "categories" },
  { type: "input", text: "数值（英文逗号分隔）", name: "values" },
  { type: "color-picker", text: "柱色", name: "barColor" },
];

export const barChartInitValue = {
  type: "bar-chart",
  title: "示例柱状图",
  categories: "订单,退款,成交,取消",
  values: "120,30,80,12",
  barColor: "#409eff",
  style: { width: "340", height: "200" },
};

src/components/BarChart.vue 本体用纯 SVG 画柱子，不依赖任何图表库：

vue
<template>
  <svg :width="box.w" :height="box.h">
    <rect
      v-for="(v, i) in values"
      :x="..."
      :y="..."
      :width="barWidth"
      :height="(v / maxValue) * box.h"
      :fill="barColor"
    />
  </svg>
</template>

运行时注册：app.registerComponent("bar-chart", BarChart)；编辑器侧回填：propsConfigs["bar-chart"] = barChartFormConfig、propsValues["bar-chart"] = barChartInitValue。

3. 横幅：点击 → code action ​

dsl.ts 里 code block 预定义：

ts
codeBlocks: {
  code_welcome_alert: {
    name: "welcomeAlert",
    params: [{ name: "msg", type: "text" }],
    content: ({ params }) => alert(params?.msg || "tmagic 运行时"),
  },
},

DSL 里某个组件的 events：

ts
{
  type: "button",
  id: "btn_1",
  events: [{
    name: "magic:common:events:click",
    actions: [{ actionType: "code", codeId: "code_welcome_alert", params: { msg: "hello" } }],
  }],
}

4. 动画卡：flip method 被 comp 联动 ​

组件本体要在 instance 上挂方法。lab 里这么做：

ts
// AnimatedCard.vue
const flipped = ref(false);
const flip = () => {
  flipped.value = !flipped.value;
};

onMounted(() => {
  const instance = node?.instance;
  if (instance) instance.flip = flip;
});

AnimatedCard.meta.ts 的 methods 数组声明：

ts
export const animatedCardMethods = [{ name: "flip", text: "翻转卡片" }];

在 eventMethodList["animated-card"].methods 里回填后，编辑器右侧 COMP 联动面板就能找到 flip。

5. 数据源：接一条 HttpDataSource ​

lab 没展开 HttpDataSource 示例，但接入步骤很清晰：

ts
// data-sources/my-http-ds.ts
import { HttpDataSourceSchema } from "@tmagic/data-source";
import { HttpDataSource } from "@tmagic/data-source";

export class MyHttpDataSource extends HttpDataSource {
  get type() {
    return "my-http";
  }
  // 可以重写 beforeRequest / afterResponse 做鉴权或数据整形
}

// runtime/main.ts
DataSourceManager.register("my-http", MyHttpDataSource);

然后在编辑器左侧"数据源"面板"新增"按钮里选择 my-http，填 URL / method / responseOptions，运行时 app.dataSourceManager.addDataSource(config) 会被自动调。组件里想用这个数据源的字段，formConfig 写 { type: "data-source-field-select" } 即可。

6. 预览 → 发布 ​

完整发布链路走 @tmagic/cli，lab 跳过了。如果你要做完整流水线，推荐路径：

  1. 把 labs/tmagic-editor 拆成两个独立工程：labs/tmagic-editor/editor（设计器）+ labs/tmagic-editor/runtime（运行时）
  2. runtime 里建 tmagic.config.ts，把组件 packages 写成 npm 包路径（或保持本地路径 ./components，让 createTmagic.componentsPath 扫）
  3. runtime npm run tmagic → 生成 .tmagic/*-entry.ts 五份入口
  4. runtime npm run build:page && npm run build:libs && npm run build:playground → 产出 dist/page/、dist/playground/、dist/entry/
  5. 设计器侧 propsConfigs = asyncLoadJs(${runtimeUrl}/entry/config.js) 异步加载

但对于"教学级 lab"来说，手动 import + 手动回填足够，也更可控。

跑不起来？ ​

症状可能原因排查步骤
新组件拖入画布空白一片registerComponent key 和 DSL type 不一致打 Console：appInstance.resolveComponent('bar-chart') 返回 undefined 就是这个问题
右侧面板不显示 formConfig 字段propsConfigs 漏配 / type 不是 editor 能识别的打开控制台看 appInstance 里组件 DSL 的 type，去 propsConfigs[type] 查

code action 不执行codeId 写错 / flowState.abort 前一个 action 中断了在 EventHelper actionHandler 里临时打 log；或直接改 code block content 里抛一个 Error 看控制台
数据源注册了但找不到没在 runtime 调 DataSourceManager.register(type, cls)这个是常见漏项；register 必须在 new TMagicApp 之前 或组件 import 之后立即 调
发布预览空白runtime.html 没读到 ?localPreview=1 参数的 DSL打 Console：JSON.parse(localStorage.getItem('tmagic-lab-preview')) 有没有值

避坑清单 ​

  1. 组件的 style 字段必须是 CSS 单位字符串。{ left: 30 } 会导致绝对定位计算错乱——必须 { left: "30px" } 或 { left: "30%" }。initValue 里直接写字符串即可，编辑器会自动处理单位。
  2. formConfig 的 type 不认识时用 as any[]。运行时 @tmagic/form 支持的 type 比 FormItemConfig 声明的多（color-picker、boolean、rate、slider、date-picker 等），TS 报错但运行没问题。
  3. EventHelper 串行 await，action 里不要做 CPU 密集计算。否则画布会"卡一下"再执行完。code block 里如果要做异步（比如调接口），要显式返回 promise。
  4. 不要直接修改 DSL 对象引用。编辑器内部用 reactive 包裹，你直接 mutation 可能绕过 diff；推荐走 editorService 或在 code block 里用 setValue 等 core 提供的 API。
  5. 数据源类的 type 必须全局唯一。tmagic 内置 static（DataSouce 基类）和 http（HttpDataSource），自定义 type 不能用这两个名字。
  6. 组件 methods 数组里的名字必须真的能调。声明了 flip 但 node.instance.flip 是 undefined → COMP action 执行时会静默跳过，也不会报错。务必在 onMounted 里挂好。

小结与自测 ​

你应该记住的 ​

  • 自定义组件四件套：index.vue + formConfig + initValue + event；lab 跳过 @tmagic/cli，手动 registerComponent + 手动回填 propsConfigs / propsValues / eventMethodList
  • 事件联动三种 actionType：CODE（执行 DSL 里的 code block）/ COMP（调目标组件的 instance method）/ DATA_SOURCE（调数据源的 method 或 setData）；串行 await，flowState.abort 中断后续
  • 数据源四件套：dataSource 类 extends DataSource/HttpDataSource + formConfig + initValue + event；register 必须在 new TMagicApp 之前
  • 发布链路：@tmagic/cli tmagic entry 扫 packages，生成五份入口 → build 出 page / playground / entry 三类产物 → 编辑器异步加载 entry/*.js

自测题 ​

  1. 选择题：以下哪一种 formConfig type 能让编辑器弹出"数据源模板输入框"？（A）text；（B）input；（C）data-source-input；（D）field-select。
  2. 动手题：在 src/components/ 里写一个新组件 product-card（图片 + 标题 + 价格，formConfig 用 data-source-input 接价格字段），注册到 runtime 和 propsConfigs / propsValues，然后在 DSL 里加一个 DATA_SOURCE action 让点击卡片时刷新价格。
  3. 思考题：如果我们想做"条件显隐"——某个组件只有数据源字段 stock > 0 时才显示，用 tmagic-editor 的能力能实现吗？用什么机制？（提示：displayConds / NODE_CONDS_KEY / NO_DISPLAY_CONDS_KEY 或组件内部的 visible / condResult 字段）

自测题参考答案 ​

  1. 答案 C。data-source-input 会让编辑器显示一个"静态值 / 数据源模板"切换的输入框。
  2. 提示：商品卡片本体用 @tmagic/vue-runtime-help 的 useApp 取 app.dataSourceManager，在 formConfig 的 data-source-input 字段里允许切换到数据源模板；config.price 在运行时会被自动编译成真实值（core 的 compiledNode 做）。DATA_SOURCE action 在组件 click 时调 app.runDataSourceMethod(["stock_ds", "request"])。
  3. tmagic 通过组件 DSL 上的 displayConds 字段定义显隐条件：displayConds: [{ cond: { field: ["price", "stock"], op: ">", value: 0 } }]；core 的 compiledNode 会把它编译成 condResult（布尔）。运行时 useComponentStatus hook 会自动读取 config.visible 和 config.condResult 来决定是否渲染。lab 里 AnimatedCard 没接 displayConds，但机制已就绪。
