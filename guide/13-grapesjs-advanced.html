第 13 章 · GrapesJS 进阶：画布自由，工程不自由 ​

前置章节：第 12 章 · GrapesJS 基础
所需环境：Node 22 LTS、pnpm 9.15.4；本章 lab 仍使用原生 TypeScript + Vite 5 + grapesjs 0.23.8。
难度：★★★
本章交付物：自定义 Hero 横幅组件（带 title/subtitle/bgColor trait）、自定义插件、响应式断点切换、撤销重做。

第 12 章我们跑通了 GrapesJS 的基础能力——拖 Block、编辑画布、导出 HTML/CSS。但如果你试着拖一个 Button 进去然后改文字，你会发现属性面板只有通用的 HTML 属性（id、class、title 等），没有"按钮文字"、"按钮颜色"这种业务语义字段。运营同学看到一个"class: gjs-btn-xxxxx"肯定懵。

GrapesJS 对此的回答是 自定义组件类型 + Trait + 插件三件套：

  • DomComponents.addType 定义新的组件类型（model + view）；
  • traits 数组定义该组件在右侧属性面板显示哪些表单字段；
  • editor.Plugins.add 把一组组件/Block/Command 打包成插件，在 grapesjs.init({ plugins: [myPlugin] }) 时加载。

本章聚焦三件事：写一个带 trait 的 Hero 横幅组件、把它打包成插件、用响应式断点切换预览。lab 里还演示了 trait 变化时实时同步到画布子组件文本。

本章你将获得 ​

读完本章，你应该能完成四件事：

  1. 用 editor.DomComponents.addType 定义自定义组件类型，理解 model（defaults + traits）和 view（onRender）的分工；
  2. 配置 traits 数组，让右侧属性面板出现业务语义字段（text/color/number 等类型）；
  3. 用 editor.Plugins.add 写一个插件，在 init 时注册组件、Block、Command；
  4. 用 editor.setDevice 切换桌面/平板/手机响应式预览。

先看漫画 ​

这一话讲"画布自由不等于工程自由"——标签君写了一个 Hero 横幅但每次拖入都要手动改颜色和标题，因为属性面板没有定制字段。码叔点出三件套：DomComponents.addType 定义组件模型、traits 定义属性面板、Plugins.add 打包成可复用插件。画布自由度交给用户，工程约束留给开发者。

如果你只记住一句话：GrapesJS 的工程化能力全在 addType + traits + plugin 三件套里，不做这三件事，自由画布就是无政府主义。逐格讲解、坑点清单和三道自测题在 EP.13 漫画讲解。

从一个真实问题说起 ​

你用 GrapesJS 给运营做了一个落地页编辑器，运营反馈"每次拖横幅都要改半天"——因为属性面板只有通用 HTML 属性，改标题要双击文字、改背景色要进样式面板调色、改副标题又要双击。效率极低。

解决方案：给 Hero 横幅定义一个自定义组件类型，在 traits 里声明 title、subtitle、bgColor 三个字段。运营拖入 Hero 后，右侧面板直接出现这三个表单字段，改完画布实时更新。这就是 trait 的价值——把通用 HTML 属性抽象成业务语义字段。

原理拆解 ​

自定义组件类型：model + view ​

editor.DomComponents.addType(name, definition) 注册一个新的组件类型。definition 包含 model 和 view 两部分：

ts
editor.DomComponents.addType("hero", {
  model: {
    defaults: {
      tagName: "section",
      traits: [
        { name: "title", label: "标题", type: "text" },
        { name: "subtitle", label: "副标题", type: "text" },
        { name: "bgColor", label: "背景色", type: "color" },
      ],
      components: [
        { type: "text", tagName: "h2", content: "Hero 标题" },
        { type: "text", tagName: "p", content: "Hero 副标题" },
      ],
    },
  },
  view: {
    onRender() {
      // trait 变化时同步到子组件
      this.model.on("change:title", () => {
        const h2 = this.el.querySelector("h2");
        if (h2) h2.textContent = this.model.get("title") || "Hero 标题";
      });
    },
  },
});
  • model.defaults：组件的默认属性，包括 tagName、traits、components（子组件）、styles 等。
  • traits：右侧属性面板的字段配置。每个 trait 有 name（字段名）、label（显示名）、type（text/color/number/select/checkbox 等）。
  • view.onRender：视图渲染回调。trait 变化时 model 触发 change:<name> 事件，view 监听后更新 DOM。lab 里我们手动把 title 同步到 <h2> 文本、bgColor 同步到 el.style.background。

Trait 的类型 ​

GrapesJS 内置几种 trait type：

type渲染控件值类型
text文本输入框string
number数字输入框number
checkbox复选框boolean
select下拉选择string
color颜色选择器string（hex）
button按钮触发 command

自定义 trait 用 editor.Traits.addType(name, { createInput, ... })，返回一个 DOM 元素作为输入控件。

插件 ​

插件就是一个函数 (editor, options) => void，在 init 时被调用：

ts
const heroPlugin = (editor) => {
  editor.DomComponents.addType("hero", { ... });
  editor.Blocks.add("hero-block", {
    label: "Hero 横幅",
    category: "Custom",
    content: { type: "hero", title: "默认标题", bgColor: "#1e293b" },
  });
};

grapesjs.init({
  container: "#gjs",
  plugins: [heroPlugin],
});

插件是 GrapesJS 复用的基本单位——官方 preset（preset-webpage、preset-newsletter）都是插件，你也可以把自己的组件库打包成插件给其他编辑器用。

响应式断点 ​

editor.setDevice("Desktop" | "Tablet" | "Mobile") 切换画布宽度。GrapesJS 默认有三个断点：Desktop（100%）、Tablet（768px）、Mobile（320px）。切换后画布 iframe 宽度变化，媒体查询生效。自定义断点用 editor.Media：

ts
editor.Media.add("tablet", {
  width: "768px",
  widthMedia: "768px",
});

Commands 与 UndoManager ​

GrapesJS 的所有操作都封装成 Command：editor.runCommand('get-html')、editor.runCommand('undo')、editor.runCommand('copy') 等。内置 Command 有几十个，覆盖导出、剪贴板、设备切换、缩放等。

自定义 Command 用 editor.Commands.add(id, run, stop)：

ts
editor.Commands.add("show-stats", () => {
  const count = editor.Components.getAll().length;
  alert(`当前画布有 ${count} 个组件`);
});

然后可以在 UI 按钮上 editor.runCommand("show-stats")，或注册到快捷键。

UndoManager 管理历史栈。所有通过 model 层的修改（如 component.set('style', ...)）会自动进历史栈，Ctrl+Z 撤销。但直接操作 DOM 不会进历史——这也是为什么必须走模型层。批量操作可以用 editor.UndoManager.transaction(() => { ... }) 合并成一条历史记录。

额外补充：model 与 view 的分工 ​

GrapesJS 的组件遵循经典的 MVC 模式：model 管数据、view 管渲染。

  • model.defaults 定义组件的初始状态：tagName、traits、components（子节点）、styles、attributes。这些都是数据，不涉及 DOM。
  • view 负责把 model 渲染成 DOM，并监听 model 变化更新 DOM。onRender 是视图渲染后的回调，可以在这里挂事件监听（this.model.on('change:xxx', ...)）。

这个分工的好处是：数据和视图解耦。你可以在 model 上改 trait 值，view 自动更新；也可以在 model 上挂业务逻辑（如校验、联动），不污染 view。lab 里 Hero 组件的 view.onRender 只做一件事——监听 trait 变化并同步到子组件 DOM，所有数据都在 model 上。

对比 tmagic-editor：tmagic 的组件是纯 Vue 组件，数据和视图都在 Vue 的响应式系统里，没有明确的 model/view 分层。GrapesJS 因为是原生 JS（没有响应式框架），所以需要手动用 Backbone 风格的 model/view 来管理数据和视图的同步。

额外补充：插件为什么是函数而不是对象 ​

GrapesJS 的插件是 (editor, options) => void 函数，不是带 init 方法的对象。原因很简单：函数是闭包，可以在内部定义私有变量和辅助函数，不会污染全局；函数在 init 时被调用一次，调用时 editor 已经就绪，可以直接 editor.DomComponents.addType 等。

ts
const heroPlugin = (editor, options) => {
  // 闭包内的私有变量
  const DEFAULT_TITLE = options?.defaultTitle || "默认标题";

  editor.DomComponents.addType("hero", {
    model: {
      defaults: {
        traits: [{ name: "title", ... }],
      },
    },
  });

  editor.Blocks.add("hero-block", {
    content: { type: "hero", title: DEFAULT_TITLE },
  });
};

如果插件需要异步初始化（如加载远程 Block 列表），不要在插件函数里 await——GrapesJS 不支持异步插件。可以在 grapesjs.init 之后手动调一个初始化函数：

ts
const editor = grapesjs.init({ plugins: [heroPlugin] });
await loadRemoteBlocks(editor); // init 之后手动加载

额外补充：自由画布的工程化约束 ​

GrapesJS 的画布越自由，工程约束越重要。实际项目中通常做四层约束：

  1. Block 层：只开放业务需要的 Block，不给"通用 div"。运营只能拖 Hero、Card、Button 这些业务组件，不能随手拖一个 div。
  2. Trait 层：每个组件的 trait 只暴露业务语义字段（标题、颜色、链接），不暴露通用 HTML 属性（如 onclick、onmouseover）。
  3. 样式层：用 CSS 变量 + 类名管理样式，不让运营直接编辑 CSS。GrapesJS 的样式面板可以通过 stylePrefix 和白名单限制可编辑属性。
  4. 组件层：droppable / draggable 限制嵌套规则。比如 Hero 只能拖到 Page 根节点，不能拖到 Card 里。

不做这些约束，运营拖出来的页面会变成"div 地狱"——维护成本远高于手写 HTML。GrapesJS 的强大之处在于它给了你全部约束能力，用不用取决于工程素养。一个好的 GrapesJS 项目，运营看到的是"业务组件"，不是"HTML 标签"。这也是自由画布和专业编辑器之间的真正分界线。

动手实现 ​

1. 启动第 13 章 ​

bash
cd labs/grapesjs
pnpm dev
# 访问 http://localhost:5178/#13

左侧面板应该出现 "Custom" 分类，里面有 "Hero 横幅" Block。

2. 自定义 Hero 组件 ​

src/chapters/13-grapesjs-advanced/index.ts 里的 heroPlugin 做了三件事：

  1. DomComponents.addType("hero", {...}) 注册组件类型，traits 声明 title/subtitle/bgColor；
  2. view.onRender 监听 trait 变化，同步到子组件 DOM（h2 文本、p 文本、section 背景色）；
  3. Blocks.add("hero-block", {...}) 注册可拖入的 Block，content 指定初始 trait 值。

拖入 Hero 后，右侧属性面板会出现三个字段。改 title，画布上的 h2 立即变；改 bgColor，背景色立即变。

3. 响应式预览 ​

lab 目前没有 UI 按钮切换设备，但可以在控制台手动调：

ts
editor.setDevice("Mobile"); // 画布缩到 320px
editor.setDevice("Tablet"); // 768px
editor.setDevice("Desktop"); // 恢复

第 13 章的进阶练习是加三个按钮绑定这三个 command。

4. 撤销重做 ​

GrapesJS 内置 UndoManager，editor.UndoManager 管理历史栈。默认 Ctrl+Z / Ctrl+Shift+Z 可用。自定义命令要调 editor.UndoManager.add(historyItem) 才会进历史栈。

历史栈的本质是 model 层的属性变化快照。每次 component.set('attr', value) 都会被 UndoManager 捕获，存成 { component, attr, prev, next }。撤销时把 prev 写回，重做时把 next 写回。这就是为什么必须走模型层——直接操作 DOM 不会触发 model change 事件，UndoManager 捕获不到。

如果要做批量操作（如一键换肤），用 editor.UndoManager.transaction(() => { ... }) 把多次 set 合并成一条历史记录，避免一次操作产生几十条 undo。

避坑清单 ​

  1. addType 必须在 init 之前或插件内：在 grapesjs.init 之后调 DomComponents.addType 不会生效，因为组件类型在 init 时就被扫描。要么写在插件里随 init 加载，要么在 init 之前全局注册。
  2. traits 变化不会自动同步到子组件：model 的 trait 变化只更新组件自身属性，子组件（如 h2）不会自动变。必须在 view.onRender 里手动监听 change:<traitName> 并更新子组件 DOM。
  3. plugin 函数必须是同步的：插件函数 (editor, options) => void 不支持异步。如果要加载远程数据，在 init 之后手动调，不要放插件里。
  4. styles 的作用域是整个画布：自定义组件的 styles 会注入到 iframe <style>，可能影响其他组件。建议用唯一类名前缀（如 .gjs-hero）隔离。
  5. trait 的 type 必须用内置或已注册的：自定义 type 要先 editor.Traits.addType，否则 trait 会渲染成默认 text input 且不报错。
  6. 不要在 view 里直接改 model：view 只负责渲染和监听，改 model 要在 trait 面板或 command 里。view 直接 this.model.set(...) 会绕开 trait 的类型校验和 UndoManager。

实战建议：自定义组件的设计原则 ​

写 GrapesJS 自定义组件时，有三条原则能让你的组件既好用又好维护：

原则一：trait 只暴露业务语义，不暴露技术实现。 运营不需要知道"h2 的 textContent"，他只需要"标题"。所以 trait 的 name 应该是 title 而不是 h2Text，label 应该是"标题"而不是"h2 文本"。技术实现（哪个子组件的哪个属性）封装在 view.onRender 里。

原则二：组件自治，不依赖外部状态。 自定义组件的 model 应该包含它渲染所需的全部数据（title、subtitle、bgColor），不要依赖全局变量或其他组件的状态。这样组件可以独立拖入、独立编辑、独立导出。如果需要组件间通信，用 GrapesJS 的事件系统（editor.trigger / editor.on）而不是直接引用其他组件的 model。

原则三：样式用类名，不用内联。 虽然 GrapesJS 支持内联 styles，但自定义组件的 styles 应该写在 defaults.styles 里用类名选择器（如 .gjs-hero { ... }），而不是在每个实例上写内联 style。这样样式可以复用、可以被媒体查询覆盖、导出的 HTML 更干净。

小结与自测 ​

你应该记住的 ​

  • 自定义组件三件套：DomComponents.addType（model + view）+ traits（属性面板）+ Plugins.add（打包复用）
  • model.defaults 定义组件结构和 trait 声明；view.onRender 监听 trait 变化同步 DOM
  • trait 类型：text / number / checkbox / select / color / button；自定义用 Traits.addType
  • 插件是函数 (editor, options) => void，在 plugins: [...] 里随 init 加载
  • 响应式用 editor.setDevice 切换画布宽度，媒体查询要自己写
  • UndoManager 只捕获 model 层变化，直接操作 DOM 不会进历史栈；批量操作用 transaction 合并

自测题 ​

  2. 动手题：在 Hero 组件里新增一个 trait：{ name: "align", label: "对齐", type: "select", options: [{ value: "left", name: "左" }, { value: "center", name: "中" }, { value: "right", name: "右" }] }，并在 view.onRender 里监听 change:align，把 el.style.textAlign 设为对应值。拖入 Hero 后改对齐，看画布是否生效。
  3. 思考题：为什么 GrapesJS 用 trait 而不是像 tmagic 那样用 formConfig？两种设计的取舍是什么？（提示：trait 是组件模型的属性，formConfig 是独立的表单描述）

自测题参考答案 ​

  1. 答案 B。traits 数组决定属性面板显示哪些字段，每个 trait 的 name 是组件 model 上的属性名。
  2. 提示：this.model.on("change:align", () => { this.el.style.textAlign = this.model.get("align") || "left"; })。select 的 options 是 { value, name } 数组。
  3. GrapesJS 的 trait 是组件模型的一等属性——trait 的值直接存在 component model 上，view 监听 model 变化更新 DOM。tmagic 的 formConfig 是独立于组件的表单描述，编辑器根据 formConfig 渲染右侧面板，修改后写回 DSL。GrapesJS 的设计更"组件内聚"（属性和组件绑在一起），tmagic 的设计更"编辑器中心化"（formConfig 是编辑器侧的配置）。前者适合自由画布（组件自治），后者适合 Schema 驱动（编辑器统一管控）。
