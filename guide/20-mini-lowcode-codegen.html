第 20 章 · mini-lowcode 出码：从 Schema 到可运行系统 ​

前置章节：第 19 章 · mini-lowcode 历史与插件
所需环境：Node 20 + pnpm 9.15.4；本章 lab 在 labs/mini-lowcode，重点看 src/core/codegen.ts。
难度：★★★★
本章交付物：Schema → Vue 代码生成器、JSON 导出、HTML 转义、输出校验。

低代码平台的"最后一公里"是出码——把可视化搭建的 Schema 导出成可运行的代码。为什么要出码？因为低代码平台再强大，也总有覆盖不到的场景。出码给用户一个"逃生通道"：平台不够用时，导出代码自己改。

出码的核心是序列化：把 Schema 这棵树遍历一遍，按组件类型生成对应的代码。生成的代码必须是可运行的——不是伪代码，而是能直接 pnpm dev 跑起来的 Vue 单文件组件。

本章实现 Codegen 模块：输入 Schema，输出 { vue, json }。vue 是可运行的 Vue 组件代码，json 是 Schema 的 JSON 序列化。还要处理 HTML 转义（防止 props 里的特殊字符破坏生成的代码）和输出校验（确保生成的 vue 代码有 template、script、style 三部分）。

本章你将获得 ​

读完本章并跑通 lab，你应该能：

  1. 理解出码的本质：Schema 树遍历 + 组件类型映射到代码模板；
  2. 实现 generate(schema) 输出 { vue, json }；
  3. 处理 HTML 转义：props 里的 <、>、"、& 要转义；
  4. 实现 validateOutput(output) 校验生成的代码结构完整；
  5. 跑通 codegen 相关测试（7 条全绿）。

先看漫画 ​

这一话画的是出码的过程——像素酱把 Schema 树"翻译"成 Vue 代码，标签君看到 text 组件变成 <span>、container 变成 <div>，码叔提醒"props 要转义，否则 XSS"。逐格讲解、坑点清单和三道自测题在 EP.20 漫画讲解。

从一个真实问题说起 ​

你用低代码搭了一个页面，Schema 长这样：

json
{
  "version": "1.0.0",
  "root": {
    "id": "page-1",
    "type": "page",
    "children": [
      { "id": "t1", "type": "text", "props": { "content": "你好" } },
      { "id": "b1", "type": "button", "props": { "label": "提交" } }
    ]
  }
}

怎么把它变成可运行的 Vue 代码？直觉是：遍历这棵树，对每个节点生成对应的 HTML 标签。text → <span>，button → <button>，container → <div>，page → 根 <div>。

生成的结果应该是这样的 Vue 单文件组件：

vue
<template>
  <div class="lc-page">
    <span class="lc-text">你好</span>
    <button class="lc-button">提交</button>
  </div>
</template>
<script setup></script>
<style></style>

但有个坑：如果 text 的 content 是 <script>alert(1)</script>，直接拼进去会执行恶意脚本。必须做 HTML 转义。

原理拆解 ​

出码的本质 ​

出码 = Schema 树遍历 + 类型到代码模板的映射。和渲染器很像——渲染器是"Schema → VNode"，出码器是"Schema → 字符串代码"。

伪代码：

ts
function generate(node: SchemaNode): string {
  switch (node.type) {
    case "page":
      return `<div class="lc-page">${node.children?.map(generate).join("")}</div>`;
    case "container":
      return `<div class="lc-container">${node.children?.map(generate).join("")}</div>`;
    case "text":
      return `<span class="lc-text">${escapeHtml(node.props.content)}</span>`;
    case "button":
      return `<button class="lc-button">${escapeHtml(node.props.label)}</button>`;
  }
}

和渲染器的递归一样，出码也是递归——container 生成 <div>，然后对每个 child 递归 generate，拼进 div 内部。

模板字符串的拼接 ​

出码本质上是字符串拼接。用模板字符串（反引号）最方便：

ts
const code = `<div class="lc-page">${childrenCode}</div>`;

但模板字符串里如果有用户输入，要小心——用户输入里的 ${ 会被当成模板插值。所以用户输入必须先 escapeHtml，而且不要直接把用户输入放进模板字符串的 ${} 外面。

mini-lowcode 的做法是：先把每个节点的代码生成好（转义过的），再用模板字符串拼接结构。这样用户输入不会破坏模板字符串的语法。

HTML 转义 ​

HTML 转义是出码的安全底线。用户输入的内容（text 的 content、button 的 label）可能包含特殊字符：

字符转义后原因
<&lt;否则会被当成 HTML 标签开始
>&gt;否则会被当成 HTML 标签结束
"&quot;否则会破坏属性值的引号
&&amp;否则会被当成 HTML 实体开始

转义函数：

ts
function escapeHtml(s: string): string {
  return s.replace(
    /[<>"&]/g,
    (c) =>
      ({
        "<": "&lt;",
        ">": "&gt;",
        '"': "&quot;",
        "&": "&amp;",
      })[c],
  );
}

所有用户输入的内容都要经过转义才能拼进生成的代码。这是防止 XSS 的基本措施。

输出校验 ​

生成的代码必须是完整的 Vue 单文件组件，包含 <template>、<script>、<style> 三部分。validateOutput(output) 检查：

  1. vue 包含 <template> 标签；
  2. vue 包含 <script 标签（可能是 <script setup>）；
  3. vue 包含 <style> 标签；
  4. json 是合法的 JSON（能 JSON.parse 回去）。

如果校验失败，说明出码有 bug，不应该让用户拿到残缺的代码。

递归与终止条件 ​

和渲染器一样，出码的递归也要有终止条件——叶子节点（text/button/input）没有 children，不再递归。page 和 container 有 children，递归生成子节点的代码。

如果 Schema 有环，出码会无限递归。所以出码前最好先 validateSchema，确保树结构合法。

产品对照 ​

维度mini-lowcodelowcode-engineamis
出码方式递归 generate(node)出码插件支持出码
输出格式Vue SFC + JSONReact/Vue 代码JSON 配置
HTML 转义escapeHtml有有
校验validateOutput有有

lowcode-engine 的出码更复杂——支持出 React 和 Vue 代码，支持自定义出码插件。amis 的出码主要是导出 JSON 配置（因为 amis 本身就是配置驱动）。mini-lowcode 只出 Vue 代码，是教学版的最简实现。

动手实现 ​

1. 启动并测试出码 ​

bash
cd labs/mini-lowcode
pnpm dev          # http://localhost:5180

在控制台调用：

ts
const output = generate(schema);
console.log(output.vue); // Vue 代码
console.log(output.json); // JSON 字符串

把 output.vue 保存成 .vue 文件，可以直接在 Vue 项目里运行。

2. 看 codegen.ts ​

src/core/codegen.ts 导出：

  • generate(schema)：返回 { vue, json }；
  • escapeHtml(s)：HTML 转义；
  • validateOutput(output)：校验输出结构；
  • generateNode(node)：递归生成单个节点的代码。

3. 跑 codegen 测试 ​

bash
pnpm test -- codegen

7 条用例覆盖：

  1. 空 page 生成只有根 div 的代码；
  2. text 生成带转义内容的 span；
  3. button 生成带转义 label 的 button；
  4. container 递归生成子节点；
  5. HTML 转义：<script> 被转义成 &lt;script&gt;；
  6. validateOutput 通过：三部分齐全；
  7. validateOutput 失败：缺少 template。

4. 验证 XSS 防护 ​

构造一个恶意 Schema：

ts
const schema = {
  root: {
    id: "p",
    type: "page",
    children: [{ id: "t", type: "text", props: { content: "<script>alert(1)</script>" } }],
  },
};
const output = generate(schema);
// output.vue 里的 content 是 &lt;script&gt;alert(1)&lt;/script&gt;

浏览器渲染时会显示文本 <script>alert(1)</script>，而不是执行脚本。

5. 把生成的代码跑起来 ​

把 output.vue 保存为 output.vue，放到一个 Vue 项目里：

bash
pnpm create vite test-app -- --template vue
cd test-app && pnpm install
# 把 output.vue 放到 src/components/
# 修改 App.vue 引入 Output 组件
pnpm dev

你会看到和低代码画布上一样的页面。这证明出码生成的是可运行的代码，不是伪代码。

6. 看 generateNode 的递归 ​

generateNode 和渲染器的 render 结构几乎一样——switch(node.type)，容器类型递归 children。区别只是返回字符串而不是 VNode。这说明"数据驱动视图"的思想贯穿了渲染和出码——同一份 Schema，既能渲染也能出码。

7. 扩展练习：出 React 代码 ​

试着加一个 generateReact(schema) 函数，输出 React JSX。核心逻辑和 generateVue 一样，只是标签语法不同：

  • Vue：<span class="lc-text">内容</span>
  • React：<span className="lc-text">内容</span>

这个练习会让你理解出码的通用性——同一份 Schema 可以出成不同框架的代码。

8. 验证生成代码的可运行性 ​

出码的最终验收标准是"生成的代码能跑起来"。mini-lowcode 的测试里有一条 smoke 测试：把生成的 vue 代码写入临时文件，用 Vue 编译器检查是否有语法错误。

你也可以手动验证：

  1. 用 generate 生成 vue 代码；
  2. 保存为 .vue 文件；
  3. 放到 Vite + Vue 项目里；
  4. pnpm dev 看页面是否正常渲染。

如果页面渲染正常，说明出码是正确的。如果报错，检查是转义问题还是结构问题。

跑不起来？ ​

症状可能原因排查步骤
生成的代码跑不起来缺少 template/script/style用 validateOutput 检查
页面显示 HTML 标签忘记转义检查 content/label 是否经过 escapeHtml
递归栈溢出Schema 有环先 validateSchema 再出码
JSON.parse 失败json 格式错误检查 JSON.stringify 是否正确处理了所有字段

避坑清单 ​

  1. 所有用户输入必须转义：text.content、button.label 等都要 escapeHtml，否则 XSS。
  2. 生成的代码必须结构完整：template + script + style 三部分缺一不可。
  3. 递归要有终止条件：叶子节点不再递归，和渲染器一样。
  4. 出码前先校验 Schema：有环的 Schema 会导致无限递归，先 validateSchema。
  5. JSON 输出要可反序列化：JSON.stringify 后能 JSON.parse 回来，不能有循环引用。
  6. 生成的代码不要包含未转义的 script 标签：否则用户导入后会执行任意代码。

出码的局限性 ​

出码不是万能的，有些东西出不了：

  • 事件处理：低代码里配置的"点击按钮调用 API"，出码时只能生成占位函数，具体逻辑需要用户自己写。
  • 复杂联动：表单字段之间的联动逻辑，出码后可能需要用户手动补充。
  • 动态数据：Schema 里的 $&#123;&#123; expr &#125;&#125; 表达式，出码时要转成 Vue 的响应式表达式，复杂的表达式可能转不了。

mini-lowcode 的出码只处理静态结构（标签、样式、文本），不处理事件和联动。生产级引擎的出码会更完整，但也不可能 100% 还原——出码的定位是"起点"，不是"终点"。用户导出代码后通常还需要手动修改。

出码 vs 运行时渲染 ​

低代码平台有两种运行方式：

  • 运行时渲染：平台直接渲染 Schema，不出码。优点是实时性好，缺点是依赖平台运行时。
  • 出码后独立运行：导出代码，脱离平台运行。优点是不依赖平台，缺点是导出后无法再用平台编辑。

很多平台同时支持两种——编辑时用运行时渲染，发布时可以选出码或托管运行。mini-lowcode 只演示出码，运行时渲染就是前面章节的 Renderer。

出码在生产中的实践 ​

生产级低代码平台的出码通常分两种模式：

  • 全量出码：把整个页面导出成独立项目，用户拿到后完全脱离平台。适合需要深度定制的场景。
  • 增量出码：只导出用户修改过的部分，其他部分继续由平台渲染。适合大部分只需小改的场景。

全量出码的好处是灵活，坏处是导出后无法再用平台编辑；增量出码的好处是可回平台继续编辑，坏处是仍然依赖平台运行时。

出码还需要考虑代码风格——生成的代码要符合 ESLint 规范，要有合理的缩进和注释，否则用户拿到后很难维护。mini-lowcode 没有做代码格式化，生产级引擎通常会接入 Prettier 格式化生成的代码。

小结与自测 ​

你应该记住的 ​

  • 出码本质：Schema 树遍历 + 类型到代码模板的映射，和渲染器结构相似
  • HTML 转义是安全底线：<、>、"、& 必须转义，防止 XSS
  • 生成的代码必须结构完整：template + script + style
  • 递归要有终止条件，出码前先校验 Schema（防止环导致栈溢出）
  • 出码是低代码的"逃生通道"，但不可能 100% 还原复杂逻辑
  • 出码生成的代码要做格式化（Prettier），保证可维护性
  • 运行时渲染和出码各有优劣，很多平台同时支持

自测题 ​

  1. 选择题：出码时为什么要做 HTML 转义？（A）为了代码美观；（B）防止 XSS 攻击；（C）提高性能；（D）减少代码体积。
  2. 选择题：出码生成的 Vue 单文件组件必须包含哪三部分？（A）template、script、style；（B）html、css、js；（C）head、body、script；（D）template、data、methods。
  3. 思考题：出码和运行时渲染有什么区别？什么时候选出码，什么时候选运行时渲染？

自测题参考答案 ​

  1. 答案 B。用户输入的内容可能包含 <script> 等恶意代码，如果不转义直接拼进生成的 HTML，浏览器会执行这些脚本。转义后 < 变成 &lt;，浏览器会把它当作文本显示，而不是标签解析。
  2. 答案 A。Vue 单文件组件（SFC）的标准结构是 <template>（模板）、<script>（逻辑）、<style>（样式）三部分。缺少任何一部分，Vue 编译器都会报错。
  3. 运行时渲染是平台直接解析 Schema 生成界面，优点是实时编辑、所见即所得，缺点是依赖平台运行时；出码是把 Schema 转成独立代码，优点是脱离平台运行、可自由修改，缺点是导出后无法再用平台可视化编辑。编辑阶段用运行时渲染，发布阶段如果要完全脱离平台就选出码，如果继续托管就选运行时渲染。
